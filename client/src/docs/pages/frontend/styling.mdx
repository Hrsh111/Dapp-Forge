# Best Practices

Frontend development best practices for Dapp-Forge.

## 🎯 Component Design

### 1. Single Responsibility

```javascript
// ✅ GOOD: Component does one thing
class OrderBook extends Component {
  render() {
    return <OrderList orders={this.props.orders} />
  }
}

// ❌ BAD: Component does too much
class OrderBook extends Component {
  render() {
    return (
      <div>
        <OrderList />
        <PriceChart />
        <Trades />
      </div>
    )
  }
}
```

### 2. Props vs State

```javascript
// ✅ GOOD: Use props for parent data
class Component extends Component {
  render() {
    return <div>{this.props.data}</div>
  }
}

// ✅ GOOD: Use state for local UI
class Component extends Component {
  state = { isOpen: false }
  
  render() {
    return <Modal open={this.state.isOpen} />
  }
}
```

### 3. Controlled Components

```javascript
// ✅ GOOD: Controlled input
<input
  value={this.state.value}
  onChange={(e) => this.setState({ value: e.target.value })}
/>

// ❌ BAD: Uncontrolled
<input ref={this.inputRef} />
```

## 🔄 State Management

### 1. Redux Patterns

```javascript
// ✅ GOOD: Descriptive action types
const LOAD_ORDERS_SUCCESS = 'LOAD_ORDERS_SUCCESS'

// ✅ GOOD: Action creators
const loadOrdersSuccess = (orders) => ({
  type: LOAD_ORDERS_SUCCESS,
  orders
})

// ✅ GOOD: Pure reducers
const reducer = (state = initialState, action) => {
  switch(action.type) {
    case LOAD_ORDERS_SUCCESS:
      return { ...state, orders: action.orders }
    default:
      return state
  }
}
```

### 2. Selectors

```javascript
// ✅ GOOD: Use createSelector for memoization
import { createSelector } from 'reselect'

const getOrders = state => state.orders
const getFilters = state => state.filters

const getFilteredOrders = createSelector(
  [getOrders, getFilters],
  (orders, filters) => {
    return orders.filter(order => 
      order.price >= filters.minPrice
    )
  }
)
```

### 3. Avoid Deep Nesting

```javascript
// ✅ GOOD: Flat state structure
{
  orders: { ... },
  trades: { ... },
  account: { ... }
}

// ❌ BAD: Deeply nested
{
  exchange: {
    orders: {
      data: {
        items: [ ... ]
      }
    }
  }
}
```

## ⚡ Performance

### 1. Memoization

```javascript
import { memo } from 'react'

// ✅ GOOD: Memoize expensive components
const OrderRow = memo(({ order }) => (
  <tr>
    <td>{order.price}</td>
    <td>{order.amount}</td>
  </tr>
))
```

### 2. Avoid Inline Functions

```javascript
// ✅ GOOD: Bind in constructor
constructor() {
  this.handleClick = this.handleClick.bind(this)
}

render() {
  return <button onClick={this.handleClick}>Click</button>
}

// ❌ BAD: Creates new function on every render
render() {
  return <button onClick={() => this.handleClick()}>Click</button>
}
```

### 3. Virtual Scrolling

```javascript
// For large lists
import { FixedSizeList } from 'react-window'

<FixedSizeList
  height={400}
  itemCount={1000}
  itemSize={35}
>
  {Row}
</FixedSizeList>
```

## 🔒 Security

### 1. XSS Prevention

```javascript
// ✅ GOOD: React escapes by default
<div>{userInput}</div>

// ⚠️ DANGEROUS: Only if you trust the source
<div dangerouslySetInnerHTML={{__html: trustedHTML}} />
```

### 2. Input Validation

```javascript
// ✅ GOOD: Validate inputs
const validateAmount = (amount) => {
  if (!amount || isNaN(amount)) return false
  if (parseFloat(amount) <= 0) return false
  if (parseFloat(amount) > MAX_AMOUNT) return false
  return true
}
```

### 3. Safe External Links

```javascript
// ✅ GOOD: Prevent tab-nabbing
<a 
  href={url} 
  target="_blank" 
  rel="noopener noreferrer"
>
  Link
</a>
```
